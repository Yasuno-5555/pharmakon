# World Model Agent — Implementation Plan

**Date**: 2026-05-09
**Status**: Implemented (2026-05-09) — Phase 5a-5e complete. `orchestration/world.rs` deployed, `agent.rs` wired for Deep tasks.
**Target**: Phase 5 (Self-Evolving Intelligence → World Model Reasoning)

## 1. Motivation

Current CodeAct executes scripts reactively: generate → run → observe error → retry.
It has no internal model of the environment. Each failure is discovered only at runtime.

World Model Agent shifts the paradigm:
```
Before acting → Simulate internally → Select best plan → Execute once → Verify
```

Instead of N retries wasting real API calls and filesystem mutations, the agent runs
cheap internal simulations (MCTS + DryRun + Cargo Check in temp workspace) and only
commits the winning plan to the real filesystem.

## 2. Existing Components (Already Implemented)

| Component | Location | Capability |
|-----------|----------|------------|
| `MctsSimulatorTool` | `orchestration/mcts.rs` | Simulate N options in isolated temp workspace, run `cargo check`, rank by success |
| `RlfcTool` | `orchestration/rlfc.rs` | LLM-driven fix loop using Clippy feedback. Causal memory edges (`caused_by`, `fixed_by`) |
| `SnapshotStore` | `snapshot_store.rs` | Content-addressed file snapshots before mutation. `restore(snapshot_id)` for atomic rollback |
| `EventLog` | `event_log.rs` | Append-only JSONL. Records `FileMutated`, `ToolCalled`, `ToolResult` with causal hashes |
| `rollback_to_event()` | `agent.rs` | Walk event log in reverse, restore all files to pre-mutation state |
| `DryRunTool` | `codex/dry_run.rs` | Simulate shell/patch/API calls without side effects |
| `CounterfactualSimulatorTool` | `codex/counterfactual_simulator.rs` | "What if this approach fails?" analysis |
| `DeterministicReplayTool` | `codex/deterministic_replay.rs` | Replay traces using recorded results instead of re-executing |
| `ParallelExecutor` | `orchestration/parallel.rs` | DAG-based parallel task execution with dependency ordering |
| `CodeAct` | `orchestration/codeact.rs` | Model-adaptive script execution (Python/Rhai auto-detection) |
| `CognitiveBudget` | `orchestration/cognitive_economics.rs` | Token budget with shadow price, EVPI gating, optimal ceiling |
| `AgentEconomy` | `orchestration/dsge_integration.rs` | Live model routing, regime detection, production function fitting |

**Architectural insight**: These components already cover 80% of the World Model Agent loop.
What's missing is the orchestrator that ties them together into a single coherent flow.

## 4. Implementation Phases

### Phase 5a: Plan Representation & Validation

**File**: `crates/core/src/orchestration/world.rs` (new)

```rust
/// A candidate action plan generated by the LLM.
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CandidatePlan {
    pub id: String,
    /// Human-readable description of the approach.
    pub description: String,
    /// Estimated token cost for this plan.
    pub estimated_tokens: u64,
    /// Steps to execute (CodeAct scripts or tool calls).
    pub steps: Vec<PlanStep>,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct PlanStep {
    /// Tool name to invoke.
    pub tool: String,
    /// Arguments for the tool.
    pub args: serde_json::Value,
    /// Dependencies on previous step indices (for ParallelExecutor).
    pub depends_on: Vec<usize>,
    /// Dry-run first? (true for destructive operations).
    pub dry_run_first: bool,
}

/// Validation result for a plan step.
pub struct PlanValidation {
    pub plan_id: String,
    pub valid: bool,
    pub issues: Vec<String>,
    /// Estimated success probability from MCTS simulation.
    pub mcts_score: f64,
    /// Estimated token cost.
    pub token_cost: u64,
    /// EVPI: how much new information this plan would provide.
    pub evpi: f64,
}
```

**Dependencies**: None (pure data structures + serde)

### Phase 5b: Plan Generator (LLM Prompt)

**File**: `crates/core/src/orchestration/world.rs` (add to existing)

```
pub async fn generate_candidate_plans(
    agent: &Agent,
    task: &str,
    context: &str,
    max_plans: usize,
) -> Result<Vec<CandidatePlan>>
```

- Constructs a structured prompt asking the LLM to output 3-5 JSON plans
- Each plan has steps with tool names, args, and dependencies
- The prompt includes available tools from `ToolMetaRegistry`
- Plans are parsed and validated (no syntax errors, no policy violations via `PolicyEngine`)

**Dependencies**: `agent.model`, `agent.registry`, `agent.policy_engine`

### Phase 5c: Simulation Engine

**File**: `crates/core/src/orchestration/world.rs` (add to existing)

```
pub async fn simulate_plan(
    agent: &Agent,
    plan: &CandidatePlan,
) -> Result<PlanValidation>
```

For each plan:
1. **Snapshot current state** via `SnapshotStore::snapshot_file()` for all files the plan touches
2. **Create temp workspace** (reuse MCTS's `copy_dir_recursive`)
3. **Execute steps in temp workspace** using `ParallelExecutor` (respecting `depends_on`)
4. **Run `cargo check`** to verify compilation
5. **Score the result**: `mcts_score = f(success, estimated_tokens, evpi, diff_complexity)`
6. **Discard temp workspace**
7. Return `PlanValidation` with scores

**Dependencies**: `SnapshotStore`, `MctsSimulatorTool.simulate_option()` (refactored), `ParallelExecutor`

### Phase 5d: Commit & Rollback Loop

**File**: `crates/core/src/orchestration/world.rs` (add to existing)

```
pub async fn execute_world_model(
    agent: &Agent,
    task: &str,
) -> Result<String>
```

The main orchestration loop:

1. **Generate plans** (Phase 5b)
2. **Simulate all plans** (Phase 5c) — parallel via `tokio::join!`
3. **Select best plan** by `mcts_score`
4. **If best plan's `mcts_score < threshold`**: fall back to standard CodeAct
5. **Commit**:
   - `SnapshotStore::snapshot_file()` for each file the plan touches
   - Record `event_id` from EventLog checkpoint
   - Execute plan steps via `CodeAct` or direct tool calls
   - Run `RLFC` for validation
6. **If commit fails**:
   - `rollback_to_event(event_id)` — atomic restore
   - Try next-best plan from simulation results
7. **If all plans fail**: return error with diagnostics

**Dependencies**: All of the above + `RLFC`, `rollback_to_event()`

### Phase 5e: Integration with Agent Loop

**File**: `crates/core/src/agent.rs` (modify)

In `chat_on_session()`, after task classification:

```rust
let complexity = classify_task_complexity(user_message, model.as_ref()).await;

if complexity == TaskComplexity::Deep {
    // World Model path: simulate before acting
    match world::execute_world_model(&self, user_message).await {
        Ok(result) => return Ok(result),
        Err(e) => log::warn!("World Model failed ({}), falling back to CodeAct", e),
    }
}
// Standard CodeAct path for Simple/Standard tasks
```

### Phase 5f: Scoring Function Refinement

The initial scoring function uses heuristics. After collecting trajectory telemetry
(via `TrajectoryTelemetry` struct already in `dsge_integration.rs`), the scoring
function can be refitted online:

```
mcts_score = w1 * cargo_pass (0/1)
           + w2 * (1.0 - token_cost / budget.remaining)
           + w3 * evpi
           + w4 * (1.0 - hallucination_risk)
```

Weights `w1..w4` are initialized as `[0.5, 0.2, 0.2, 0.1]` and updated via
online linear regression from `TrajectoryTelemetry` outcomes.

## 6. Risk Assessment

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| Simulation too slow for real-time use | Medium | Temp workspace is lightweight (no git clone). Use `copy_dir_recursive` only for relevant files. Set 30s timeout per simulation. |
| LLM generates invalid JSON plans | High | Validate with `serde_json::from_str`. On failure, ask LLM to retry with error context (RLFC-style feedback loop). |
| Simulation results don't match real execution | Medium | This is fundamental to any world model. Mitigated by: (1) `cargo check` is deterministic, (2) snapshot-based rollback makes failures cheap, (3) scoring weights adapt from real outcomes. |
| Token cost of simulation exceeds savings | Low | Simulation uses cheap model for `cargo check` (no API cost). LLM generates plans once. EVPI gating skips simulation for low-novelty tasks. |
| PolicyEngine blocks simulated mutations | Low | Temp workspace is isolated. PolicyEngine only applies to real filesystem mutations. |

## 7. Success Criteria

1. **Deep tasks complete in fewer iterations** than standard CodeAct (measured via `TrajectoryTelemetry.tool_call_count`)
2. **Zero unrecoverable filesystem mutations** — rollback works on all failure paths
3. **Simulation accuracy > 80%** — `cargo check` in temp workspace predicts real outcome
4. **No regression** on Simple/Standard tasks (they skip the World Model path)
5. **Plan generation latency < 5s** (one LLM call with structured output)

## 8. Open Questions

1. **Should plans be cached?** If the same task appears again, can we reuse a previously simulated plan? (Answer: yes, via `SkillGenome` — plans that succeed get crystallized as reusable patterns.)

2. **How to handle non-Rust projects?** MCTS currently runs `cargo check`. For other languages, we need language-specific verification commands. The `PlanStep` should include a `verify_command` field.

3. **Multi-agent simulation?** Can we simulate a swarm where each agent tries a different plan? (Answer: yes — `FractalSwarmTool` + `GeneralEquilibrium` already provide the allocation mechanism. This is Phase 6.)

4. **When does the World Model path activate?** Initially: only for `TaskComplexity::Deep`. After telemetry collection: when `EVPI > threshold` (the expected value of simulating exceeds the simulation cost).
